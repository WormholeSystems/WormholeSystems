# The API

There is one API: the JSON surface under `/api/` that the map screen itself uses. Every
read the frontend makes and every action it takes is an endpoint there, and all of it
accepts a personal access token in place of the session cookie. A script can do whatever
a person at the screen can do, with the same rules applied.

The old application's API is not carried over. A client written against it needs to be
pointed at the endpoints below instead.

## The document

The API is described by an OpenAPI 3.1 document generated from the handlers and wire
types themselves, so it is complete and current by construction:

- `GET /api/openapi.json` on any instance serves it.
- `GET /api/docs` renders it as a browsable reference (Scalar), with a request runner.
- [`openapi.json`](./openapi.json) is the committed copy for the code in this checkout.

The committed copy is regenerated by `cargo test` (the `openapi` test writes it, the same
way the TypeScript bindings under `frontend/src/lib/api/types/` are written), and CI fails
when it differs from what is in git. So a handler cannot change shape without the document
changing with it.

Every handler carries a `#[utoipa::path]` attribute naming its parameters, body,
responses and security, and every wire type derives `ToSchema` next to its `TS` derive.
The routers are built with `routes!()`, which refuses a handler without the attribute, and
a test checks no area module registers a route any other way. Adding an endpoint means
writing the attribute; there is no separate document to keep in step.

## Authentication

A user mints a token under **Settings, API tokens**. The plaintext is shown once; only its
SHA-256 hash is stored ([`personal_access_tokens`](./database/authentication.md#personal_access_tokens)).
Send it as a bearer header:

```
Authorization: Bearer wst_...
```

A token acts as the user who made it, flying their preferred character, with exactly the
access that user has signed in: the same roles, the same maps, nothing more. An unknown,
revoked or expired token answers `401` on every request. Tokens themselves are managed
only from a browser session: `/api/me/tokens` refuses a bearer token, so a leaked one
cannot mint a replacement.

The document declares two security schemes, `bearer` and `session` (the cookie a browser
holds), and applies both to everything by default. An operation with an empty security
requirement is public. The map reads that a share link opens (`GET /api/maps/{id}`, the
signatures, the watchlist, and so on) also take a `share` query parameter and say so.

## Errors

Every error is `{ "error": "..." }` with the matching status:

| Status | Meaning |
|--------|---------|
| `400`  | The request does not make sense: a missing field, a value out of range, or a body naming a different map than the URL. |
| `401`  | Nobody is signed in, or the token is unknown, revoked or expired. |
| `403`  | Signed in, but the role on this map does not allow it. |
| `404`  | No such thing, or not one the caller may know about. |
| `409`  | The change contradicts the map's current state. |
| `502`  | EVE's API refused or failed (waypoints). |
| `500`  | Something failed on our side. The body says only that; the detail goes to the server log. |

## Conventions

- Map actions are `POST /api/maps/{id}/<area>/<verb>` with a JSON body that carries
  `map_id` again. The two must agree, so a URL can never act on a map it does not name.
- A `null` body on `200` means done and nothing to say; the WebSocket says what changed.
- Mutations publish an event and the screen refetches. A script that wants to see its own
  change reflected should read again after the call, or follow the event stream.

## Realtime

Live updates go over WebSockets, which OpenAPI cannot describe. They are in
[`realtime-api.md`](./realtime-api.md).

## Stability

The API is the frontend's, and it changes with the frontend. This is beta software:
endpoints are renamed and bodies gain and lose fields between updates. The `version` in
the document's `info` is the server's crate version. Pin what you tested against and
expect to revisit when it moves. When the beta label comes down, the stability promise
will be made here, and the document's version is where it will be kept.
